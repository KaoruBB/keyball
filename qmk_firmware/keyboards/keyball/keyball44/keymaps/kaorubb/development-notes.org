#+title: kaorubb 開発・移行記録

この文書は、配列の移行経緯、設計判断、検証結果の記録。
導入と日常操作は[[README.org][ユーザー向けREADME]]、任意のバックアップと復旧は[[recovery.org][復旧手順]]を参照する。

* 設計と移行の方針

- Linux USの4レイヤーを0〜3、Mac USを4〜7、Windows JISを8〜11へ割り当てた。
- 数字レイヤーとは独立した、3プロファイル共通のマウスレイヤーを12へ追加した。
- レイヤー状態は16bit。使っていなかった各プロファイルのLayer 2は記録として残し、入口を追加しない。
- 初期の手動切替版は起動時にLinuxを選択し、OS選択はEEPROMへ保存しなかった。
  現在は接続時のOS自動判別と、1キーによる循環切替へ変更した（下記参照）。
- QMK本体は0.29.0、コミット=75a037d2f0f9c54bad8e2f68ae82134559c92f22=へ固定。
  元のファームウェアREADMEの0.22.14とは異なり、既存workflowの版に合わせた。
- 初回書き込みで左右のキーとポインタが反転したため、44基板の極性に合わせて
  =SPLIT_HAND_MATRIX_GRID_LOW_IS_LEFT=を個人用設定へ追加した。
- 数字キーを保持したままOSを切り替えても、解放時に旧プロファイルのレイヤーが復活しないよう状態を制限した。
- 左右のスクロールキーを別々に追跡し、一方の解放で他方の保持を解除しない。

* 元配列との照合

元の資料は[[../../../../../../keyball44/doc/recovery/keymap_cheatsheet_keyball44.pdf][Linux PDF]]と
[[../../../../../../keyball44/doc/recovery/keymap_cheatsheet_keyball44_mac.pdf][Mac PDF]]。
表示名だけではMod-Tap等のキーコードを特定できないため、実機のVIA配列とも照合した。

RemapのPDFでは、キー上部の修飾表示は同時入力、下部はホールド動作。
=*=の左右位置は左／右修飾キーを示す。
たとえばLayer 1のH位置はShift+左クリックという同時入力であり、Mod-Tapではない。
Layer 2のCtrl+数字も同時入力として保存する。

| 項目                             | 実装                                                                                                                 |
|----------------------------------+----------------------------------------------------------------------------------------------------------------------|
| LINUX の S/L ホールド           | 左／右 GUI （ Super ）                                                                                              |
| MAC の S/L ホールド             | 左／右 Alt                                                                                                           |
| LINUX の SPACE                   | タップ SPACE 、ホールド左 Alt                                                                                       |
| MAC の Space                     | 通常の Space                                                                                                         |
| MAC の左下の F3                 | タップ F3 、ホールド左 Ctrl                                                                                         |
| MAC LAYER 1 の D/F               | タップ 8/9 、ホールド左 Shift/GUI                                                                                   |
| LINUX LAYER 1 の N/M/カンマ位置 | GUI+X / Page Down / Page Up                                                                                          |
| MAC LAYER 1 の N/M/カンマ位置   | N / M / カンマ                                                                                                       |
| LAYER 3 の I 位置                | Linux は F12 、 Mac は F8 （ PDF の違いをそのまま保存）                                                            |
| Linux Layer 0 左下の透明キー    | 下位レイヤーがないので=KC_NO=（入力なし）                                                                          |
| LAYER 3 の Space/Backspace 位置  | PDF の透明キーから Linux/Mac 選択キーへ変更                                                                        |
| MUTE と音量                      | 実機の VIA 読み取り結果に合わせて Keyboard Mute / Volume を使用。 Consumer キー用の=EXTRAKEY=は無効              |
| LAYER 2 の JIS Hiragana          | 実機で=KC_LNG4=と確認。 International 2 ではなく Language 4 を使用                                                 |
| MAC LAYER 3 の Q 位置            | 実機の通常 F11 から、利用者の選択で PDF の Ctrl/F11 へ変更                                                        |
| OLED                             | OS名・プロファイル内レイヤー番号、ボール移動量・CPI・スクロール状態、レイヤー状態・自動マウス状態を表示 |
| LED                              | Step 6 で容量を確保するため、利用者の選択により単色点灯のみを維持                                                |

LEDはPlainとオン／オフを維持する。アニメーションを選ぶ既存キーは配列に残るが、
対応するエフェクトは無効。Step 5までのアニメーションはStep 6では利用できない。
PDFのDebug Toggleキーは保存するが、Consoleは無効なのでデバッグ出力はない。

PDFからは現行ファームウェアのタップ判定時間、TTのタップ回数、CPI、スクロール設定、
自動マウス設定は分からない。上記の標準値と実機の現在の動作との違いは、書き込み前後に確認する。


* Windows JISの記号とIME

Windowsモードだけ、QMK Key OverridesでUSの論理キーをJISキーコードへ変換する。
Shiftなし・ありの両方を扱い、Mod-Tapのタップも補正する。
OS切替時には補正中のキーを解除する。

当初は無変換・変換を割り当て、Microsoft IME側で機能を設定する方針だった。
貸与PCで追加ソフトやIMEのキー再設定を必要としない操作を優先し、
標準IMEのImeOff / ImeOnを直接送る構成へ変更した。

| 位置 | 実装 |
|------+------|
| LinuxでTTの位置 | =LT(WIN_NUM, KC_LNG2)= |
| 右Alt位置 | =RALT_T(KC_LNG1)= |

Windowsの左キーはタップでIMEオフ、ホールドで数字レイヤー。
TTの5回タップ固定はWindowsに追加しない。Linux/MacのTTは維持する。

参考：[[https://docs.qmk.fm/features/key_overrides][QMK Key Overrides]]、
[[https://learn.microsoft.com/ja-jp/windows-hardware/design/component-guidelines/keyboard-japan-ime][MicrosoftのImeOn / ImeOff仕様]]。

* LEDと容量

初期移行ではSnake・Knight・Static Gradient・Alternatingを省き、PDFにあるエフェクトを維持した。
Windowsの記号補正追加時に30,202 / 28,672 bytesとなり、1,530 bytes超過した。
利用者の選択により、Breathing・Rainbow Mood・Rainbow Swirl・Christmas・RGB Test・Twinkleも無効化。
現在はPlainとオン／オフを維持している。

* OS自動判別と循環切替

3つの選択キーを=PROFILE_CYCLE=へ一本化した。
設定レイヤーの左Space位置を押すたびにLinux → Mac → Windows → Linuxへ進む。
左Backspace・右Shift位置は透明へ戻した。
Muteのホールドを継続したまま複数回循環できるよう、設定レイヤーの保持をキーマップ側で管理する。

QMK 0.29.0のOS DetectionでUSBのセットアップ通信からOSを推定する。
Linux / macOS / Windowsを各プロファイルへ対応付ける。iOS判定など未対応の判定はLinuxを維持する。
不明な判定では起動時のLinuxを維持する。
手動切替後は、同じ接続中の遅い判別通知を無視する。

USBが設定済み／サスペンド状態から初期化状態へ戻ると、新しい接続として扱う。
その時点でUSBの判別データを消し、手動優先を解除する。
通常のサスペンド／復帰だけでは手動優先を解除しない。
自動切替は全物理キーの解放後、タップ／ホールドの確定時間が経過してから適用する。

=profile-selection.h=はQMKに依存しないOS選択の状態遷移。
同じCコードをホストでコンパイルし、不明判定、各OSの選択、入力中の延期、循環、
遅い判定より手動優先、再接続後の自動復帰という6シナリオをテストする。
生成HEX/ELFの配列表テストと合わせて=verify_firmware.py=から実行する。

参考：[[https://docs.qmk.fm/features/os_detection][QMK OS Detection]]。
実際のUSB判別と、Mute保持中の循環・解放は実機で確認する。特にWindows実機は未確認。

砂嵐の調査中は直近キー位置を追加した表示で28,642 / 28,672 bytesとなり、配列検証と状態遷移の計12テストが成功した。
