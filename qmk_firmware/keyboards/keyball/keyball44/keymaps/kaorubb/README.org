#+title: Keyball44 kaorubb ユーザーガイド

右ボールのKeyball44へ、このリポジトリのLinux US・Mac US・Windows JIS配列を導入する手順。
作業用PCはLinuxまたはApple Silicon Mac、キーボードはPro Micro / ATmega32U4とCaterinaが対象。
以下のコマンドはすべて、cloneしたリポジトリのルートで実行する。

* 初めて導入する

** 1. リポジトリと開発環境を用意する

PCにGit、Nix（flakes有効）、direnv、nix-direnvを用意し、direnvのシェル連携を有効にする。
ソースを取得し、direnvにこの開発環境の読み込みを許可する：

#+begin_src sh
git clone --branch kaoru/qmk_migration https://github.com/KaoruBB/keyball.git
cd keyball
direnv allow
#+end_src

既にclone済みなら、そのリポジトリで続きを行う。
初回は依存のダウンロードが終わり、シェルのプロンプトが戻るまで待つ。

** 2. キーマップからファームウェアを生成する（ビルド）

次のコマンドは、=keymap.c=の配列をキーボードに書き込めるHEXファイルへ変換する。
初回は固定版のQMK本体（0.29.0）も自動取得する：

#+begin_src sh
bash bin/build-keyball44.sh kaorubb
#+end_src

成功すると、末尾に=Firmware:=と生成先を表示する。
生成先は=tmp/qmk-0.29.0/keyball_keyball44_kaorubb.hex=。
=The firmware is too large!=やエラーが出た場合は、書き込みへ進まずビルドの問題を解消する。

direnvのシェル連携を使わない場合は、各コマンドの前に=direnv exec .=を付けて実行できる。
例：=direnv exec . bash bin/build-keyball44.sh kaorubb=。

** 3. 生成した配列を検証する

次のコマンドは、生成したHEXとELFを読み、キー配置・OS別配列・Windows記号補正・容量を検査する：

#+begin_src sh
python3 qmk_firmware/keyboards/keyball/keyball44/keymaps/kaorubb/verify_firmware.py -v
#+end_src

末尾に=OK=と表示されれば成功。失敗した場合は原因を確認してから書き込む。

** 4. 左右へ同じファームウェアを書き込む

作業対象のKeyball44だけをUSB接続する。左右接続ケーブルは接続したままでよい。
USBを接続している側へ書き込む。左右接続ケーブルを抜き差しする場合は、先にUSBを外す。
PCのOSに合う手順を使う。

*** Mac

まずUSBを左側へ接続する。次のコマンドはリセット後に現れるポートを待ち、HEXを書き込んで読み戻し検証する：

#+begin_src sh
make -C tmp/qmk-0.29.0 SKIP_GIT=yes keyball/keyball44:kaorubb:avrdude
#+end_src

=Waiting for USB serial port - reset your controller now=が出たら、左側の物理リセットを素早く2回押す。
=bytes of flash verified=とavrdudeの成功終了を確認する。
USBを外して右側へ挿し直し、同じコマンド・右側のリセット操作を繰り返す。

*** Linux

USBを左側へ接続する。次のコマンドは配列を再検証し、sudo認証後にリセットを待って書き込む：

#+begin_src sh
python3 bin/keyball44-avr.py flash left --sudo
#+end_src

=Press the physical reset button twice now=が出たら、左側の物理リセットを素早く2回押す。
=left flash write and verification completed.=を確認する。
USBを外して右側へ挿し直し、右側を同様に書き込む：

#+begin_src sh
python3 bin/keyball44-avr.py flash right --sudo
#+end_src

右側のリセットを2回押し、=right flash write and verification completed.=を確認する。

** 5. 接続先のOSを選んで動作を確認する

起動時はLinuxモード。下の「OS切替」で接続先を選ぶ。
Macへ接続した場合は、入力を試す前にMacを選択する。

- 左右の文字・Space・Backspace・Enter・Shift、接続先の記号とショートカットを確認する。
- 数字レイヤー、ボールの移動方向、クリック・ドラッグ・スクロールを確認する。
- マウス操作後にキーを離すと保持が解除され、通常入力へ戻ることを確認する。

* 日常操作

** OS切替

左Spaceの2つ左にあるMuteを押し続け、選択キーを一度押してから両方を離す。

| 選択キーの位置 | モード | OLED表示 |
|----------------+--------+----------|
| 左Space | Linux US | =Linux US L0= |
| 左Backspace | Mac US | =Mac US L0= |
| 右Shift | Windows JIS | =Win JIS L0= |

接続し直すとLinuxへ戻る。選択中のOSは保存しない。
USBを接続する側でOSを使い分ける必要はない。

** 数字レイヤーとWindowsのIME

タップは短く押して離す操作、ホールドは押し続ける操作。

| モード | キー位置 | タップ | ホールド |
|--------+----------+--------+----------|
| Linux / Mac | 左Spaceのすぐ左 | 5回タップで数字レイヤーを固定／解除 | 数字レイヤー |
| Windows | 左Spaceのすぐ左 | 英語入力（IMEオフ） | 数字レイヤー |
| Windows | 右Alt位置 | 日本語入力（IMEオン） | 右Alt |

Windowsの左キーに5回タップの固定機能はない。Enterは別のキーとして維持する。

** マウスとLED

ボールを動かすとマウスレイヤーへ入り、OLEDに=Mouse=と表示する。

| キー | 操作 |
|------+------|
| M | 左クリック。押し続けてボールを動かすとドラッグ |
| カンマ | 右クリック |
| ピリオド | 押している間スクロール |

数字・設定レイヤー中は、その配列が優先される。
マウス操作を終えてキーを離し、少し待つと通常の文字入力へ戻る。
数字レイヤーのZを保持するスクロールも使える。
LEDは単色点灯。Muteを保持してTab位置を押すとオン／オフを切り替える。

* Windowsで使う
:PROPERTIES:
:CUSTOM_ID: windows-jisstep-6
:END:
Windows側を「日本語キーボード（106/109キー）」に設定してから、Windowsモードを選ぶ。
対応する標準IMEでは、上の親指キーで英語／日本語を直接選べる。

入力欄で次を確認する：

- 数字レイヤーのShift+1〜0が =!@#$%^&*()=、引用符・コロン・括弧・バックスラッシュも期待どおりになる。
- 左右のIMEキーを繰り返しタップしてもモードが反転せず、ホールドでは数字／Altとして動く。
- Ctrl+A/C/V/Z、Alt+Tabと、マウスの保持・解放が正常。

Windows JISとIMEの動作は、現時点でWindows実機未検証。

* 配列を編集する

[[keymap.c][keymap.c]]を編集し、「ビルド→検証→左右への書き込み→動作確認」を繰り返す。
配列を変更した場合は、[[verify_firmware.py][配列表テスト]]の期待値も変更内容に合わせる。
VIAは無効のため、Remapでは編集できない。

* 補足

- バックアップは任意。保存・復旧が必要なら[[recovery.org][バックアップと復旧手順]]を参照する（Linux専用）。
- =command not found=が出る場合はdirenv環境を確認し、必要なら=direnv exec .=経由で実行する。
- Intel Macは現在の固定Nixpkgsの依存構成に非対応。Macの導入手順はApple Siliconを対象とする。
- ビルドで検出できない入力やマウスの動作は実機で確認する。
- 移行経緯・設計判断・検証記録は[[development-notes.org][開発・移行記録]]にまとめている。
